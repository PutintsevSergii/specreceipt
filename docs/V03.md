# SpecReceipt v0.3.1 distribution contract

The npm name and executable are `specreceipt`. The package, installed Python engine and TypeScript engine all report 0.3.1; protocol version remains 1 and product configuration schema remains 2. The older `my-ai-harness` name is retained only where needed to recognize v0.1.0/v0.2.0 baselines and the existing managed `AGENTS.md` section. Existing 0.3.0 installations remain eligible for managed upgrade. The [v0.2 guide](V02.md) documents that earlier release and its commands.

Install the reviewed local tarball in a separate tooling consumer. `specreceipt init --target DIR --dry-run` previews changes. Install OpenSpec 1.14.3 in `DIR/.harness/tools/openspec` before applying `init --yes`. `doctor --target DIR --json` diagnoses the installed project without repairing it. The CLI delegates lifecycle commands to the integrity-checked project-installed Python engine.

Existing v0.1.0/v0.2.0 projects use `specreceipt upgrade --target DIR --dry-run` and then `upgrade --target DIR`. Supply `--baseline /path/to/original/node_modules/my-ai-harness` when original bytes are needed to merge customization. Legacy baseline identity is checked without executing old package code. Overlapping changes, damaged managed files, unknown package versions, and modified Python engine code block the upgrade. The installer journal supports `upgrade --recover` after inspecting an interrupted operation.
Existing v0.3.0 projects use the same upgrade commands and their recorded file baselines; no legacy package baseline is required for an intact v0.3.0 manifest.

Runtime support: Node >=20.19 and <25, Python >=3.11, macOS/Linux or native Windows x64. Use `specreceipt.cmd` or the repository `harness.cmd` launcher on Windows; WSL is not required. Git is required for divergent text merges. OpenSpec, CodeGraph, Graphify and agent CLIs have separate installation and authentication requirements. `doctor` and local test results do not establish hosted CI or public registry behavior.
