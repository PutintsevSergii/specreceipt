# Optional OpenSpec specification provider

Status: Accepted for harness maintenance
Decision authority: User request in this session to implement OpenSpec integration, 2026-10-23.

OpenSpec 1.14.3 is an optional provider for active, repository-local changes. The existing native workflow remains available. OpenSpec sources are read directly: the change documents, specification deltas, baseline specs and project config form the bound source. Harness spec/plan files hold approval metadata and source pointers, not copied feature requirements. Project-wide onboarding and architecture gates continue to apply.

A new feature is imported from an explicitly supplied execution mapping matching the tasks schema. Import does not infer scope, approve implementation, overwrite an existing feature or accept prior completion. It adds the exact OpenSpec structural validation command to every task. Behavior checks and review remain mandatory. Source changes invalidate the binding and execution evidence; refreshing makes wrappers DRAFT and requires reviewed replanning for unfinished work. Checkbox-only progress in the bound change's tasks.md is normalized and never implies DONE.

Installation uses an isolated npm prefix under .harness, with install scripts and telemetry disabled. Agent instructions are generated by the pinned real CLI in a temporary directory and copied additively after conflict checks. Codex, Claude Code and GitHub Copilot are supported init selections; none creates only the OpenSpec structure. Generated paths receive both Git ignore layers. Existing corporate OpenSpec configuration is preserved, and conflicting agent instruction files are not overwritten. No cloud-agent workflows or global skills are installed.

This first adapter supports active local changes with the standard spec-driven schema. It does not manage external stores, custom artifact layouts, automatic archive/sync or migration of previously tracked OpenSpec files. Archive and sync can change bound inputs: do not archive a linked change while its harness record remains active. Retain historical sources and use a reviewed migration for moving them. This limitation avoids silently rewriting completion evidence.

Primary sources reviewed:
- https://github.com/Fission-AI/OpenSpec/blob/main/package.json
- https://openspec.dev/docs/cli
- https://github.com/Fission-AI/OpenSpec/blob/main/docs/supported-tools.md

Validation combines deterministic adapter tests with an explicitly enabled real 1.14.3 CLI run. Navigation-index calls are isolated by the onboarding test fixture; live CodeGraph availability is not inferred from these tests.
